# 动态 A2UI 与界面验收

日期：2026-10-30。本版替代此前默认 fixed-schema 页面；历史报告保留在 .local/diagnostics，不能用其通过结果代表当前动态生成。

## 当前实现

普通对话由 ADK LlmAgent 使用 AUTO function calling 自主处理。Agent 可以直接回答、澄清、读取业务记录或调用 generate_a2ui。生成工具使用模型组合组件图，而不是从页面模板列表中选择。组件目录包括 Row、Column、Card、通用 Form / Field、DataTable、Notice、菜品及购物车控件。

模型生成的 JSON 经过真实 React 目录 schema、组件引用图、价格总额及确认参数校验，才作为 A2UI v0.9 操作通过 AG-UI 发送给官方 renderer。布局错误允许一次模型修正；格式规范化只处理代码围栏、嵌套 props 和等价的容器引用，不补写业务或页面内容。

Agent 已选择带界面契约的业务工具时，异步 after-tool hook 调用真实模型组合器并在同一 TOOL_CALL_RESULT 内返回界面，不能用一句打开表单的承诺结束。这是工具结果契约，不是自然语言关键词路由。没有额外的执行审查模型或自然语言关键词路由，普通问答可以直接结束。按钮命令来自经校验的 forwardedProps，实际业务执行一次，后续允许生成界面和只读查询。

- 前端 TypeScript 检查通过。没有声称完整 Playwright 或生产构建已通过。

## 实时模型检查

当前机器使用 DOT，未使用 Mock Mode。最新状态及逐项证据：

- .local/agent-behavior-report.json：自然推荐、预算请求、能力问答、不要卡片的澄清、菜单 UI、一般解释。宽泛预算请求允许 Agent 选择偏好表单或实际菜单界面，不把某个工具名当作唯一正确路径。
- .local/checkout-regression-report.json：真实加购、需要时的澄清、直接结账的实际 quote_order、确认按钮、未知商品错误及生成纠错界面。较早一轮通过，购物车仍为 S$14，未提交订单；后续代码的最新状态以报告为准，不把早期通过当作全量通过。
- 较早 fixed-schema 点餐全链路结果另作历史记录，不代替本版动态 UI 的验收。

## 页面与实际交互

Agent 采用居中消息流。输入框固定、居中，最大宽度 780px；桌面菜品卡片为两列，窄屏单列。数量与加购动作放在一致的卡片 footer，菜品详细配方改为可展开内容。没有右侧工作区或 Open dining cards 入口。

新界面会自动进入可见区；普通聊天、表单、卡片和表格使用同一消息流。后端表单及订单错误可以由 Agent 再调用生成工具呈现 Notice 和纠正操作，而不是只能回退为文字。

## 边界

Gemini 因本机未配置 Key 而未进行实时验证。开放对话的事实、语义和任意布局没有穷尽测试，单次模型延迟也不是保证。菜单、订单和预订都是本地教学数据，没有支付、真实厨房或配送连接。保留 .env 私有凭据，所有修改仅在本地和本地教学仓库副本保存，没有推送或部署。

## 本轮 DOT 结果与剩余问题

- 40 项本地测试通过。
- 直接 API 对照：流式与非流式均有真实函数调用成功，JSON 组件图生成成功；重复 token 上限参数已消除。
- 一轮六项真实 DOT 行为检查完成：普通推荐、预算、能力问答、不要卡片、菜单卡片、一般解释。该轮只证明对应断言通过，不能代表任意回复事实全部正确。
- 一轮结算/纠错五步完成，实际报价 S$14，未提交订单。最新含糊同意回归仍失败：DOT 会把“需要”误猜为加菜。
- 浏览器真实显示了可编辑的通用 Form / Field 表单；发现模型额外放入一个同动作 Button 后，新增了拒绝重复提交按钮及模型修复机制。后续浏览器普通推荐又出现纯文字承诺，说明 DOT 的指令遵循仍不稳定。
- 人工检查预算回复发现文字总价误算，业务价格与按钮校验没有被绕过，但聊天事实质量仍有限。

保留 DOT 配置，不切换模型供应商；没有用预设页面或固定话术掩盖失败。延迟仍随模型输出和图修复次数变化，已通过的单次 UI 约 8–19 秒，复杂多工具预算案例约 35 秒，不承诺任意请求秒回。

历史布局证据：780px 输入框、两列各约 572px，数量与加购按钮纵向对齐，截图 .local/preview/a2ui-two-column-grid.png。该单项不代表完整稳定性通过。
